'@ogygia/image': minor
---

New package `@ogygia/image`: list `image({ presets })` from `@ogygia/image/vite` beside `ogygia()`, read an image with `import.meta.og.image('./hero.jpg')` (or many with `import.meta.og.image.glob('./gallery/*.jpg')`), and render it with `<Img of={hero} preset="cover" alt="…" />`. The build reads each source once (its size and a blur placeholder of a few hundred bytes at most) and encodes nothing; `<Img>` picks the files from a preset or its own `layout` (`constrained`, `fullWidth`, `fixed`), `width`, `aspect` and `position`, and names each one by a signed URL that the image endpoint makes on first request, in dev, in a prerender (each file starts as its page renders and lands beside it, a `layOut()` CSS background too, so `adapter-static` sites need no server) and on a live server. `import.meta.og.image(src, { warm: 'cover' })` makes a preset's files at build as static files for pages rendered on a live server. Crops are real files (a `1/1` thumbnail downloads a square), a fixed 48-pixel avatar asks for 48 and 96 only, animated GIFs become animated WebP, SVGs are served as they are, and a changed or unsigned URL is refused. `priority` preloads the page's main image from the head, `morph` names an image for a view transition, and the HTML carries no client script and no inline event handler (the placeholder and a crop are inline styles, the placeholder a `data:` image). The server loads sharp on the first image request, never at start; it keeps its files on disk to a size, answers from memory when the disk cannot write, sends a URL with a query string to the bare URL, and answers 503 past a bounded line of encodes. `layOut()` gives the same answer outside the component, and `isImage` checks a frontmatter image field (`v.custom<ImageDescriptor>(isImage)`). A missing file, a file outside `src/`, a non-literal argument, an unknown option, an unknown preset, a size of 0 or less (fractions are rounded) or an image too large to encode fails with a code.
